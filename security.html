1. System Architecture Overview

UTTAKALA OS is an offline-first, client-driven Android productivity application paired with optional cloud sync and snapshot backup utilities. The system architecture is divided into three strictly compartmentalized tiers:

TIER 1 • LOCAL STORAGE

Private Android Room/SQLite database residing in internal application data directory. Completely offline capable.

TIER 2 • CLOUD SYNC

Supabase PostgreSQL database with Row-Level Security (RLS) over TLS 1.3. Synchronizes habits, tasks, timetables, and analytics.

TIER 3 • SNAPSHOT BACKUPS

Google Drive AppData folder (`drive.appdata`). Houses unencrypted JSON snapshot files controlled by the user's Google account.

By designing the system in independent operational tiers, UTTAKALA OS guarantees that sensitive private records can be physically withheld from network transmission without sacrificing the convenience of multi-device synchronization for daily routines.

2. Local SQLite Sandbox

The core engine of UTTAKALA OS executes on Android utilizing Google's recommended Jetpack Room persistence abstraction over SQLite. The underlying database files are stored inside: 

/data/data/com.uttakala.lifeos/databases/uttakala_os.db
/data/data/com.uttakala.lifeos/databases/uttakala_os.db-wal
/data/data/com.uttakala.lifeos/databases/uttakala_os.db-shm

Under Android's Linux UID sandbox model, other third-party apps installed on the device cannot read or modify these files unless the device is rooted or the user explicitly grants system debugging access.

The Salticor Security Guard submodule (as illustrated in interface screenshot 09-salticor-security.png) enforces application-level authentication (PIN or Android BiometricPrompt) before allowing the UI thread to initialize SQLite DAOs for restricted modules.

3. Secret Diary Isolation Boundary

The Secret Diary module (screenshots 15-secret-diary-locked.png and 16-secret-diary-unlocked.png) represents our strictest privacy tier. Its architectural boundaries are verified as follows:

CRITICAL BOUNDARY GUARANTEE:
  • Secret Diary records are stored strictly in the local device SQLite tables.
  • Secret Diary records are filtered out before Supabase cloud sync payloads are constructed.
  • Secret Diary records are excluded from Google Drive AppData JSON snapshot generators.
  • Secret Diary entries are never sent to any external server or analytics pipeline.

Consequence of Local-Only Isolation: If a user uninstalls UTTAKALA OS without making a manual export, or loses their physical Android device, Secret Diary entries cannot be recovered from any cloud service. This is an intentional security tradeoff prioritizing user sovereignty over remote backup convenience.

Audit Note [OWNER REVIEW REQUIRED]: Secret Diary entries are protected by Android's application sandbox and UI PIN gate. Do not claim cryptographic zero-knowledge at-rest database encryption (e.g., SQLCipher) unless verified in the production Android build.

4. Supabase Cloud Sync Protocol

When cloud sync is enabled, UTTAKALA OS communicates with our Supabase PostgreSQL infrastructure to ensure cross-device consistency for daily productivity data:

Data Category Sync Status Protection Mechanism
Daily Tasks & Habits Synced PostgreSQL Row-Level Security (RLS) tied to Supabase UID
Timetable & Attendance Synced PostgreSQL RLS with TLS 1.3 transit encryption
Focus Timer Sessions Synced PostgreSQL RLS with TLS 1.3 transit encryption
Financial Logs Synced PostgreSQL RLS with TLS 1.3 transit encryption
Secret Diary EXCLUDED Physical network exclusion (Never sent to Supabase)

Row-Level Security Enforcement: All Supabase tables use PostgreSQL policies configured such that read, insert, update, and delete statements are valid only when auth.uid() = user_id. No user can access or view another user's database records.

5. Google Drive AppData Backups

UTTAKALA OS provides integration with Google Drive (as displayed in screenshot 17-google-drive-backup.png) to allow users to generate disaster recovery snapshots.

When a user authorizes Google OAuth, the app requests the specific, least-privilege scope: 

https://www.googleapis.com/auth/drive.appdata

What AppData means: This scope restricts UTTAKALA OS to its own dedicated, hidden application folder within your Google Drive. UTTAKALA OS cannot read, modify, or view any of your personal files, Google Docs, photos, or spreadsheets. Conversely, other third-party apps cannot view UTTAKALA OS's AppData folder.

6. Unencrypted JSON Disclosure

EXPLICIT SECURITY DISCLOSURE • RAW JSON BACKUPS

Google Drive backup payloads uploaded by UTTAKALA OS are stored as unencrypted JSON snapshots. UTTAKALA OS does NOT apply client-side zero-knowledge encryption to these backup files prior to upload.

It is critical not to confuse Google Drive's hidden AppData folder with client-side cryptographic encryption:

  • Transit Security: Data is encrypted in transit between your Android device and Google's servers via TLS 1.3.
  • Google At-Rest Security: Data is stored on Google Drive servers protected by Google's standard server-side storage encryption.
  • No Independent Cipher: If someone gains unauthorized access to your personal Google Account, they would have the technical ability to download and parse the raw JSON data stored in the AppData folder.
  • User Recommendation: We strongly advise all UTTAKALA OS users to enable Two-Factor Authentication (2FA) on their personal Google Accounts to protect their cloud backups.

7. Threat Model & System Boundaries

Security is defined by honest threat modeling. Here are the realistic boundaries of the UTTAKALA OS client environment:

Physical Device Theft / Loss

If a phone is stolen while locked, Android's hardware-backed Full Disk Encryption (FBE) and the UTTAKALA OS Salticor PIN lock prevent extraction. If a device is unlocked and handed to an attacker, the PIN gate prevents unauthorized opening of the Secret Diary.

Rooted Android Environments

On a rooted Android device, the operating system's sandbox guarantees are void. Root users or malicious root-privileged apps can inspect any SQLite database file on the filesystem. Users operating rooted devices assume responsibility for safeguarding local data.

Third-Party Telemetry & Ad Trackers

There are zero third-party commercial SDKs (no Adjust, AppsFlyer, Facebook Graph, or Google AdMob) integrated into UTTAKALA OS. Your behavioral metrics, habit completion rates, and daily focus times are never sold or shared.

8. Vulnerability Reporting & Disclosure

We take potential security vulnerabilities seriously and adhere to coordinated vulnerability disclosure practices.

If you identify a potential security vulnerability in our Android client, Supabase PostgreSQL configuration, or OAuth implementation, please email our lead developer directly:

Email: uttakalaos@gmail.com
Subject: [SECURITY VULNERABILITY] UTTAKALA OS

Please provide a detailed proof of concept, affected version, and reproduction steps. We will acknowledge receipt within 48 hours and work with you to patch verified defects prior to public disclosure.
